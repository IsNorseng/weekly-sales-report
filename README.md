# Еженедельная выгрузка для отчёта по продажам

В 2025 году я написал рабочий скрипт для подготовки данных к еженедельному отчёту коммерческого директора. Он заменил ручные выгрузки, очистку данных и постоянное копирование между таблицами одним запуском: на выходе получалась таблица для присоединения к отчёту.

Подготовка и заполнение отчёта занимали около **3 часов**. Со скриптом этот процесс сократился до **5–20 минут**.

В 2026 году я обновил и доработал проект для портфолио: уточнил расчёты, оформил ноутбук и добавил Excel-выгрузку на шесть листов. Теперь публикую его в открытом доступе с условными названиями и синтетическими данными. Указанная экономия времени относится к использованию рабочего скрипта в 2025 году.

[Ноутбук](weekly_report.ipynb) объясняет порядок расчётов. [Python-скрипт](weekly_report.py) выполняет тот же процесс без Jupyter. [Пример Excel-выгрузки](examples/report_demo.xlsx) позволяет посмотреть результат без запуска кода. Денежные показатели выручки и прибыли здесь не рассчитываются.

## Что получается

В `report.xlsx` сохраняются шесть листов:

| Лист | Содержание |
| --- | --- |
| Параметры | Период, режим запуска и настройки расчёта |
| По_дням | Показатели по дням из PostgreSQL |
| По_офферам | Показатели по офферам из SQL Server |
| По_партнёрам | Показатели по партнёрам из SQL Server |
| Отклонения | Пары партнёр–оффер с низкой конверсией или средним чеком |
| Курсы | Последние курсы перед концом периода, отдельная справочная выгрузка |

Период задаётся двумя датами: начало включается, конец исключается. Например, `2026-11-09` — `2026-11-16` означает неделю с 9 по 15 ноября включительно. Определения показателей и правила обработки статусов описаны рядом с расчётами в ноутбуке.

## Быстрый запуск

```bash
python -m pip install -r requirements.txt
python weekly_report.py
```

По умолчанию включён демонстрационный режим с синтетическими данными. Он работает без подключения к базе. В Jupyter достаточно открыть ноутбук и выполнить все ячейки по порядку.

Если Jupyter ещё не установлен: `python -m pip install jupyterlab`, затем `python -m jupyterlab`. Открывайте ноутбук из папки проекта, чтобы `.env` и выгрузка находились рядом с ним.

При повторном запуске `report.xlsx` заменяется. Перед запуском закройте его в Excel.

## Подключение к базе

1. Установите дополнительные зависимости: `python -m pip install -r requirements-db.txt`.
2. Для SQL Server установите системный драйвер **ODBC Driver 18 for SQL Server**.
3. Скопируйте `.env.example` в `.env` и заполните параметры подключения.
4. Сопоставьте условные таблицы и поля SQL-запросов со своей схемой. Уточните соответствие статусов, фильтров и валют.
5. В настройках выбранного файла поменяйте `MODE = "demo"` на `MODE = "database"`, задайте период и запустите расчёт.

`PG_OFFER_ID` и `PG_GEO` — необязательные фильтры PostgreSQL. Пустое значение отключает соответствующий фильтр. Настройки валют находятся в коде рядом с остальными параметрами. В режиме базы при пустых датах берётся последняя полная неделя с понедельника по воскресенье по Москве.

В примере PostgreSQL хранит время лидов в Unix seconds, SQL Server — московское время без часового пояса, `fx_rates.rate_at` — тоже московское время. При другой структуре адаптируйте преобразование дат в SQL. Значения статусов приведены к `pending / approved / rejected / trash / excluded`, тип лида SQL Server — к `standard`, одобрение — к `0/1`. Это условные значения, их нужно сопоставить с источником.

Средний чек считается только по одобренным заказам, отдельно по офферу и валюте. Конверсия партнёра сравнивается со всеми лидами того же оффера и валюты, включая самого партнёра. В список отклонений попадают группы от 80 лидов: конверсия ниже базы более чем на 5 п.п. или чек ниже 80% базового. Это повод проверить группу, а не причина отказа по конкретному заказу. `active_partners` считает всех партнёров с лидами. Курсы не участвуют в расчёте чеков. Выборки двух баз не складываются.

В публичной версии используются условные названия и синтетические записи. Реальные пароли и адреса подключения нужно хранить в локальном `.env`, который не следует добавлять в репозиторий. Подключение к рабочим базам в этой версии не проверялось.

В репозитории `examples/report_demo.xlsx` содержит только демонстрационные данные. При запуске создаётся отдельный `report.xlsx`, исключённый через `.gitignore`, чтобы после подключения баз случайно не опубликовать рабочие показатели. Статусы лидов читаются на момент запуска; повторная выгрузка старого периода может измениться. Две базы читаются независимо.

## Как обновлять Excel-отчёт

Для ручного переноса откройте `report.xlsx` и скопируйте нужную таблицу.

Для подключения откройте итоговый отчёт в Excel и выберите **Данные → Получить данные → Из файла → Из книги Excel**. Укажите `report.xlsx`, выберите нужные именованные таблицы и загрузите их в отчёт. Названия таблиц сохраняются между запусками.

Затем каждую неделю запускайте скрипт за новый период и нажимайте **Данные → Обновить всё** в итоговом отчёте. Само обновление Excel не запускает Python и не меняет период выгрузки.
